# Potato

Potato — открытый Telegram-юзербот для собственной установки через Docker. Одновременно работает один выбранный аккаунт; сохранённые Telegram-сессии можно переключать. Potato загружает Python-модули, обрабатывает команды и сообщения, запускает периодические задачи и принимает вебхуки модулей.

## Запуск

Понадобятся Docker Compose и `api_id` с `api_hash` вашего приложения, полученные на [my.telegram.org](https://my.telegram.org). Укажите их в `.env`:

```sh
cp .env.example .env
```

Заполните `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и `POTATO_SOURCE_URL`. Последний параметр должен вести на доступные исходники запущенной версии. Затем соберите образ и авторизуйте аккаунт:

```sh
docker compose build
docker compose run --rm potato python -m potato login
docker compose up -d
docker compose logs -f potato
```

При входе вводятся номер, код Telegram и, если включена, пароль 2FA. Авторизация хранится в постоянном томе `potato_data`. После пересоздания контейнера повторный вход не требуется. Для разработки без Docker установите зависимости из `requirements.lock`, затем используйте `python -m potato login` и `python -m potato run`; каталог данных тогда по умолчанию `./data`.

Если код не доставляется, а аккаунт уже открыт на другом устройстве, войдите по QR-коду:

```sh
docker compose run --rm potato python -m potato login --qr
```

На авторизованном телефоне откройте Telegram → Настройки → Устройства → Подключить устройство и сканируйте QR-код в терминале. Истёкший QR-код обновляется автоматически. При включённой двухэтапной проверке введите пароль 2FA в терминале. Не пересылайте изображение QR-кода другим людям.

Контейнер работает без root. HTTP-сервер слушает порт 8080 внутри контейнера, а Compose публикует его только на `127.0.0.1`. Для внешних вебхуков настройте обратный прокси с HTTPS; `POTATO_BIND_PORT` меняет локальный порт на хосте.

## Управление

Команды начинаются с точки. Настройками управляет авторизованный аккаунт; доступ другим пользователям задаётся отдельно.

Регистр не важен: `.status` и `.STATUS` работают одинаково. Между точкой и именем допускаются пробелы: `. status`. Эти правила действуют и для команд пользовательских модулей; имена команд могут содержать русские буквы.

Встроенные ответы используют HTML-разметку Telegram: цитаты, выделение текста и эмодзи. Если кастомный эмодзи недоступен аккаунту, используется обычный. Команды своего аккаунта заменяются результатом в том же сообщении; на входящие разрешённые команды Potato отвечает отдельным сообщением. `.help` показывает фактически загруженные модули и команды в формате `▪️ Модуль: ( команда | команда )`. Без пользовательских модулей доступны 15 системных модулей.

| Модуль | Команды и действие |
| --- | --- |
| APILimiter | `.api_fw_protection` включает или выключает ограничение API-вызовов; `.suspend_api_protect <секунды>` временно его приостанавливает. |
| Evaluator | `.e <выражение>` вычисляет арифметику на Python; `.ec`, `.ecpp`, `.eg`, `.enode`, `.ers` собирают или запускают код на C, C++, Go, Node.js и Rust. |
| Help | `.help` перечисляет модули и команды; `.helphide <модуль>` переключает видимость в справке; `.support` показывает ссылку на поддержку. |
| PotatoAccounts | `.addacc <имя>` запускает вход для дополнительной Telegram-сессии; `.switchacc <имя>` выбирает активную сессию и перезапускает Potato. |
| PotatoConfig | `.config`, `.cfg` читают и меняют параметры, объявленные модулем в `CONFIG`. |
| PotatoInfo | `.info`, `.ubinfo`, `.status` показывают состояние; `.inline` показывает username и состояние inline-бота; `.modules` перечисляет загруженные модули; `.source` показывает исходный код; `.webhooks` показывает маршруты и секреты в «Избранном». |
| PotatoSecurity | `.owneradd`, `.ownerlist`, `.ownerrm` управляют дополнительными владельцами; `.newsgroup`, `.sgroups`, `.sgroup`, `.sgroupadd`, `.sgroupdel`, `.delsgroup` управляют группами доступа; `.security` задаёт постоянное правило для команды; `.tsec`, `.tsecrm`, `.tsecclr` управляют временным доступом; `.inlinesec` задаёт права inline-команд; `.querysec` ограничивает доступ к inline-запросам. |
| PotatoSettings | `.nonickchat`, `.nonickchats`, `.nonickuser`, `.nonickusers`, `.nonickcmd`, `.nonickcmds` управляют исключениями NoNick; `.settings` меняет общие настройки; `.watchers`, `.watcher`, `.watcherbl` управляют обработчиками сообщений. |
| Loader | `.addrepo`, `.delrepo` управляют источниками модулей; `.loadmod`, `.dlmod`, `.dlmall`, `.lm`, `.ml` готовят модули к установке; `.unloadmod`, `.clearmodules` готовят удаление; `.restart` применяет очередь и перезапускает Potato. |
| Settings | `.aliases`, `.addalias`, `.delalias` управляют алиасами; `.blacklist`, `.unblacklist`, `.blacklistuser`, `.unblacklistuser` блокируют и разблокируют чаты и пользователей; `.togglecmd`, `.togglemod` включают команды и пользовательские модули; `.clearmodule`, `.cleardb` очищают данные; `.setprefix` задаёт дополнительный префикс; `.potato`, `.installation` показывают сведения о проекте. |
| Terminal | `.terminal`, `.exec` выполняют команду оболочки; `.terminate` останавливает запущенную команду. |
| Tester | `.ping` измеряет отклик Telegram; `.logs`, `.clearlogs` показывают и очищают ошибки модулей; `.suspend` временно останавливает обработку команд и сообщений. |
| Translations | `.setlang` выбирает язык интерфейса; `.dllangpack` загружает пользовательский языковой пакет. |
| Translator | `.tr` переводит текст команды или сообщения, на которое вы ответили. |

Для `.e` доступны числа, скобки, `+`, `-`, `*`, `/`, `//`, `%`, `**`, константы `pi`, `e` и функции `abs`, `round`, `sqrt`, `sin`, `cos`, `tan`, `log`, `log10`. Калькулятор работает в любом чате для основного аккаунта. Импорт, присваивание, обращение к атрибутам и произвольный код отклоняются. Команды `.ec`, `.ecpp`, `.eg`, `.enode`, `.ers` требуют соответствующих инструментов в контейнере, принимаются только в «Избранном» и запускают переданный код с правами процесса Potato.

Чтобы разрешить чужую команду, используйте `.security ping public` или правило `group:<имя>`; `.tsec user <ID> ping 1h` выдаёт временный доступ. Дополнительные владельцы могут выполнять обычные команды владельца, но команды с ограничением `primary_only` остаются доступными только основному аккаунту. В группе чужая разрешённая команда по умолчанию адресуется как `.ping@имя_аккаунта`. Команда `.ping` без адреса сработает, если включён NoNick для всех групп (`.settings nonick on`), этого чата (`.nonickchat`), пользователя (`.nonickuser <ID>`) или команды (`.nonickcmd ping`). NoNick влияет только на обращение к аккаунту и не выдаёт права доступа. В личном чате адрес не требуется.

`.watchers` показывает модули с `@on_message`. `.watcher <модуль>` переключает обработчик глобально; флаги `-c`, `-p`, `-o`, `-i` задают фильтр групп, личных чатов, исходящих и входящих сообщений, а `-all` снимает фильтр и включает обработчик. `.watcherbl <модуль>` переключает блокировку обработчика в текущем чате. Действуют также встроенные ограничения `incoming`, `outgoing` и `pattern` самого обработчика.

Интерфейс по умолчанию русский. `.setlang en` выбирает английский, `.setlang ru` возвращает русский. `.tr` без указанного языка использует выбранный язык интерфейса. `.dllangpack https://example.org/pack.json` загружает JSON по HTTPS без перенаправлений, размером до 256 КиБ и максимум с 500 строками. Формат: `{"locale":"es","messages":{"my_module.greeting":"Hola, {name}!"},"phrases":{"Настройки Potato":"Ajustes de Potato"}}`. `messages` переопределяет строки модулей по ключу `идентификатор.ключ`; `phrases` переводит встроенные текстовые фрагменты. Пакет сохраняется отдельно для каждого аккаунта. Для переключения используйте `.setlang es`.

### Inline-бот

При запуске Potato автоматически подключает отдельного inline-бота. Сначала проверяется сохранённый токен. Если токена нет или он отозван, Potato получает список ваших ботов через официальный [BotFather](https://core.telegram.org/bots/features#botfather) и ищет username с префиксом `Potato_` без учёта регистра. Подходит любой ваш бот с таким префиксом. Если их несколько, выбирается ранее сохранённый, иначе первый по алфавиту. Поиск выполняется среди ботов текущего Telegram-аккаунта.

Если подходящего бота нет, Potato создаёт `Potato_<12 случайных латинских букв и цифр>Bot` с именем «Potato Inline». Занятый username заменяется другим, максимум пять попыток. Potato получает токен и включает inline-режим через `/setinline`. Токен сохраняется в SQLite отдельно для выбранного аккаунта и не показывается командой `.inline`. При повторном запуске готовый бот используется повторно.

После подключения юзербот автоматически отправляет `/start` своему боту. При первом запуске выберите русский или английский язык, интервал автобекапа и поддержку модулей Heroku. Быстрые интервалы: 1, 3, 6, 12, 24, 48, 96 часов; доступны собственный интервал целым числом от 1 до 876000 часов и отключение. Настройка продолжается после перезапуска. После завершения `/start`, `/help` и `/settings` открывают меню изменения настроек. Язык общий с юзерботом.

Сообщения боту, inline-запросы и кнопки доступны только владельцу текущей Telegram-сессии. Дополнительные владельцы, `.inlinesec`, `.querysec` и `owner_only=False` не открывают бота другим людям. Права обычных команд юзербота настраиваются отдельно. Отправьте `.inline`, затем в любом чате наберите `@Potato_…Bot help` или `@Potato_…Bot status`. Пустой запрос показывает справку; результат можно отправить в чат.

### Бекапы и ошибки

Potato создаёт приватную форум-группу `Potato · <ID аккаунта>` с темами «Бекап» и «Ошибки». Группа и темы используются повторно; удалённые темы восстанавливаются. Ошибки поступают фоновой очередью, известные секреты скрываются, одинаковые сообщения объединяются в течение минуты. Недоступность группы не останавливает команды.

`.bp` сохраняет исходники всех пользовательских модулей активного релиза в ZIP с манифестом и SHA-256. Архив отправляется в тему «Бекап». `.restorebp` в ответ на архив проверяет все файлы, готовит их одной операцией и перезапускает Potato через механизм релизов с откатом. Одноимённые модули заменяются, остальные сохраняются. Ограничения: 256 модулей, 1 МиБ на файл, 32 МиБ на архив и распакованное содержимое. Автобекап использует тот же формат; после простоя создаётся одна просроченная копия. Сессии, токены, настройки и кастомизация не включаются; `.bp all` пока не реализован.

### Совместимость Heroku

Поддержка включается в меню бота и разрешает установку через `.lm` и `.loadmod` модулей с `loader.Module`, `@loader.tds`, `@loader.command`, методами `…cmd`, watcher, строками `strings`/`strings_ru`/`strings_en`, `ModuleConfig`/`ConfigValue`, `get/set`, `client_ready`, `on_unload` и `@loader.loop`. Настройки доступны через `.config`. Зависимости задаются обычным `REQUIRES` либо строкой `# requires: package`.

Поддерживаются validators String, Integer, Float, Boolean, Choice, Series; фильтры watcher `in`, `out`, `only_pm`, `only_groups`, `no_commands`, `only_messages`, `regex`; utils `get_args`, `get_args_raw`, `answer`, `answer_file`, `escape_html`, `get_chat_id`, `get_topic`, `chunks`. Публичные совместимые типы и функции `herokutl` отображаются на закреплённый Telethon. Inline-формы, callback/inline/raw-обработчики, библиотеки и внутренние сервисы Heroku пока не поддерживаются. Изменение режима для уже установленных модулей применяется после `.restart`; выключенные модули сохраняются на диске.

### Задержки команд

Лимитер сохраняет общий бюджет 30 вызовов за 10 секунд и оставляет 5 мест для встроенных команд. Служебные запросы синхронизации и ping Telegram не занимают бюджет. Ожидание происходит вне общего lock. В журнале контейнера появляются длительность команд, ожидания лимитера от 100 мс и Telegram-запросы от секунды. Архивы сжимаются вне event loop; сеть и фоновые задачи не блокируют обработку команд.

### Обновление через бота

Сборка с `POTATO_BUILD_SHA` проверяет `main` репозитория `HernoBeliEzh/Potato` при запуске и каждый час. Владелец получает одно сообщение на новый SHA и кнопку «Обновиться». Для локальных сборок передавайте SHA через `POTATO_BUILD_SHA` при `docker compose build`.

Для обновления Docker на VPS установите worker на хосте:

```sh
sudo install -d -m 700 /opt/potato-updater
sudo install -d -o 999 -g 999 -m 755 /opt/potato-updater/control
sudo install -m 600 deploy/update_worker.py /opt/potato-updater/worker.py
sudo install -m 644 deploy/potato-updater.service /etc/systemd/system/potato-updater.service
sudo systemctl daemon-reload
sudo systemctl enable --now potato-updater
docker compose -p potato -f compose.yaml -f deploy/compose.updater.yaml up -d
```

Проект должен находиться в `/opt/potato`, а постоянный том — называться `potato_potato_data`. Worker принимает только SHA текущего `main` фиксированного репозитория, собирает образ и запускает тесты перед остановкой текущего контейнера. Затем сохраняет согласованный снимок тома, запускает новую сборку и проверяет healthcheck вместе с inline-ботом. При неудаче восстанавливает предыдущий образ и данные; при перезапуске worker восстанавливает незавершённую транзакцию. `.env` и снимки остаются закрытыми на хосте. Docker socket в приложение не передаётся. Состояние установки хранится в `/opt/potato-updater/current.json`; результаты доставляются через выделенный каталог `/control`.

Если BotFather заблокирован, лимит создания исчерпан или Telegram временно ограничивает запросы, Potato сообщает причину в «Избранном» и продолжает обычную работу. Исправьте причину и перезапустите сервис для повторной настройки. При локальном запуске `.restart` завершает процесс; запустите `python -m potato run` заново. В Docker сервис возвращается автоматически.

Чтобы установить модуль, отправьте `.py` файлом в Telegram и ответьте на него `.lm`. Бот проверит файл и покажет зависимости. После `.restart` зависимости устанавливаются через pip, а модуль загружается. Если установка не удалась, остаётся рабочая предыдущая версия; ошибка приходит в «Избранное».

Модули выполняются в процессе юзербота и имеют доступ к его Telegram-сессии. Устанавливайте только код, которому доверяете. Операции установки и `.restart` принимаются только от основного аккаунта. Очередь модулей применяется при `.restart`; `.dlmall` проверяет весь каталог перед изменением очереди, а `.clearmodules` убирает также файлы, ожидающие установки.

## API модулей

Каждый файл содержит один класс, наследующий `potato.api.Module`, и строку `API_VERSION = 1`. Имя файла состоит из строчных латинских букв, цифр и `_`. Максимальный размер — 1 МиБ. Необязательная переменная `REQUIRES` содержит список требований pip; допустимы пакеты с доступными бинарными колёсами, прямые URL запрещены. Пример находится в `examples/hello.py`.

Публичная версия API — `API_VERSION = 1`. Обработчики объявляются декораторами:

| Декоратор | Назначение |
| --- | --- |
| `@command("name")` | Команда владельца; `owner_only=False` открывает её другим пользователям, `aliases=("alias",)` добавляет альтернативное имя |
| `@inline_command("name")` | Inline-команда отдельного бота; поддерживает `owner_only`, `primary_only` и `aliases` |
| `@on_message(incoming=True, outgoing=False, pattern=None)` | Сообщения с необязательным регулярным выражением |
| `@interval(seconds, run_on_start=False)` | Периодическая асинхронная задача |
| `@webhook("name", methods=("POST",))` | Входящий HTTP-запрос с Bearer-секретом |
| `@webhook("name", verifier="method_name")` | Входящий запрос с собственной асинхронной проверкой подписи |

Все обработчики асинхронные. Необязательные `on_load()` и `on_unload()` вызываются при старте и остановке. Через `self.context` доступны `client` Telethon, асинхронный `http` клиент aiohttp, `storage` с методами `get`, `set`, `delete`, а также `account` и `owner_id`. Значения в `storage` должны сериализоваться в JSON и изолированы по аккаунту и модулю. Для локализации модуль может необязательно объявить `STRINGS = {"ru": {"greeting": "Привет, {name}!"}, "en": {"greeting": "Hello, {name}!"}}` и вызвать `self.context.t("greeting", name="Potato")`. Модуль без `STRINGS` продолжает работать как прежде.

Inline-обработчик получает событие Telethon `InlineQuery`: аргументы доступны в `event.potato_args`, результаты строятся через `event.builder.article(...)` и отправляются `await event.answer(results, cache_time=0, private=True)`. Используйте `private=True` и `cache_time=0` для результатов с проверкой доступа. `self.context.inline` предоставляет состояние сервиса (`ready`, `username`) и подключённый bot-клиент (`client`). Во время `on_load()` bot-клиент ещё не подключён. Пример `examples/inline_echo.py` добавляет команду `echo`: после установки через `.lm` и перезапуска наберите `@Potato_…Bot echo текст`. Inline-команды регистрируются отдельно от обычных команд; их имена также нечувствительны к регистру.

Вебхук модуля доступен по `/hooks/{account}/{module}/{route}`. По умолчанию передайте секрет в заголовке `Authorization: Bearer <secret>`. Он создаётся отдельно для каждого маршрута и виден владельцу по `.webhooks` в «Избранном». Обработчик возвращает ответ aiohttp, JSON-сериализуемое значение или `None` для HTTP 204. Для схемы подписи стороннего сервиса `verifier` должен вернуть `True` или `False` до вызова обработчика. Публичной проверки состояния достаточно по `GET /healthz`.

## Проверка установки

После запуска отправьте себе в «Избранное» `.status`. Затем загрузите `examples/hello.py` через `.lm`, выполните `.restart` и проверьте команды `.ping` и `.ticks`. Команда `.webhooks` покажет путь и секрет маршрута `notify`; запрос без секрета должен вернуть HTTP 401, а запрос с ним и JSON-полем `text` — сообщение в «Избранном». Пересоздайте контейнер и убедитесь, что повторный вход не требуется, а счётчик `.ticks` сохранился.

Потребление памяти одного аккаунта можно наблюдать через `docker stats --no-stream $(docker compose ps -q potato)` в простое и во время обработки сообщений или вебхуков. Сравнивайте замеры после одинакового времени работы и с одинаковым набором модулей.
